## 1. Цель работы

Перевести слой presentation на MVVM. Activity и Fragment создают ViewModel через `ViewModelProvider` и рисуют состояние, которое приходит в LiveData. Каталог из замоканного JSON и наблюдения из Room собираются в одном `MediatorLiveData`.

Модуль `domain` остаётся Java-библиотекой без Android. `LiveData` используется в модуле `app` и в запросе Room модуля `data`. Между экраном и use-case стоит ViewModel. Диаграмма вариантов использования из практической работы № 1 описывает те же возможности приложения.

```text
Activity / Fragment
        |  observe
        v
   ViewModel  ---- LiveData ---->  интерфейс
        |
        |  use-case
        v
   domain
        |
        +-- NetworkApi (JSON каталога)
        +-- Room sightings
```

## 2. Задание

1. Взаимодействие Activity со слоем domain идёт через ViewModel.
2. Состояние интерфейса обновляется через LiveData.
3. `MediatorLiveData` получает данные из замоканной сети и из базы.

Приложение по-прежнему выполняет вход по почте и паролю, показывает каталог из JSON, хранит наблюдения в Room, выводит список с картинками и карточку рода, различает гостя и пользователя и определяет род по модели CCSN. Поворот экрана не создаёт ViewModel заново и не повторяет уже показанный результат. `onCleared` пишет в logcat, когда экран окончательно закрыт.

| Пункт | Где сделано |
| --- | --- |
| ViewModel | `CloudViewModelFactory`, `AuthViewModel`, `SkyViewModel`, `HomeViewModel`, `DetailsViewModel` |
| LiveData | поля этих классов, `observe` в Activity и Fragment |
| MediatorLiveData | `HomeViewModel.library`: каталог JSON и `SightingDao.observeAll()` |

## 3. ViewModel

Для ViewModel подключены `androidx.lifecycle:lifecycle-viewmodel` и `lifecycle-livedata` версии 2.8.7. Фабрика одна на все экраны. Она берёт репозитории из `CloudIdApp` и передаёт во ViewModel готовые use-case. Внутри ViewModel нет `Context`, разметки и `findViewById`. Фабрика не открывает вторую базу: экземпляр `cloudid.db` тот же, что создаёт `CloudIdApp`.

Конструктор пишет в logcat `created`, `onCleared` — `cleared`.

**Листинг 1.** Создание ViewModel

```java
public <T extends ViewModel> T create(@NonNull Class<T> modelClass) {
    CloudIdApp app = CloudIdApp.get();
    if (modelClass == HomeViewModel.class) {
        return modelClass.cast(new HomeViewModel(
                new GetCloudCatalogUseCase(app.clouds()),
                new GetProfileUseCase(app.auth()),
                new GetMyAtlasUseCase(app.atlas(), app.auth()),
                new LogoutUseCase(app.auth()),
                app.observeSightings()));
    }
    ...
}
```

Экран получает модель так:

```java
viewModel = new ViewModelProvider(this, new CloudViewModelFactory()).get(AuthViewModel.class);
```

Фрагменты каталога, атласа и профиля берут одну `HomeViewModel` у `HomeActivity`, поэтому поворот и смена вкладки не перечитывают JSON заново и не теряют снимок. `SkyViewModel` хранит последний род и адрес снимка. `DetailsViewModel` не открывает карточку второй раз, если значение уже есть.

| Экран | ViewModel | Что ушло из Activity |
| --- | --- | --- |
| Вход и регистрация | `AuthViewModel` | `LoginUseCase`, `RegisterUseCase`, гостевой вход, проверка уже вошедшего пользователя |
| Кадр | `SkyViewModel` | классификация в фоне и карточка рода |
| Каталог, атлас, профиль | `HomeViewModel` | каталог, атлас, профиль, выход |
| Карточка | `DetailsViewModel` | текст рода, гость, сохранение заметки |

Пиксели для модели готовит `SkyPixels` во фрагменте: в domain нельзя передавать `Bitmap`. Во ViewModel уходит только `float[]`.

## 4. LiveData

Кнопка не записывает текст ошибки сама. ViewModel кладёт состояние в `MutableLiveData`, экран подписан и только рисует.

**Листинг 2.** Подписка на форму входа

```java
viewModel.form().observe(this, form -> {
    loginButton.setEnabled(!form.loading);
    registerButton.setEnabled(!form.loading);
    TextView target = form.register ? textErrorRegister : textError;
    if (form.error == null || form.error.isEmpty()) {
        target.setVisibility(View.GONE);
    } else {
        target.setText(form.error);
        target.setVisibility(View.VISIBLE);
    }
});
```

Переход на главный экран и выход завёрнуты в `UiEvent`. LiveData после поворота отдаёт последнее значение ещё раз, а `take()` второй раз возвращает `null`, поэтому `HomeActivity` не открывается дважды.

После поворота `SkyViewModel.result()` снова отдаёт последний род, а `DetailsViewModel` — ту же карточку и надпись «В атласе», если кадр уже сохранён.

## 5. MediatorLiveData

Каталог — это `GetCloudCatalogUseCase` и JSON `NetworkApi`. Наблюдения — это таблица `sightings`. Чтобы Room собрал запрос с `LiveData`, в модуль `data` добавлена зависимость `lifecycle-livedata`. Запрос сообщает об изменениях таблицы:

```java
@Query("SELECT * FROM sightings ORDER BY id DESC")
LiveData<List<SightingEntity>> observeAll();
```

`AtlasRepositoryImpl.observe()` переводит строки в `Sighting`. `HomeViewModel` подписывает один `MediatorLiveData` на этот поток и на каталог. Когда приходит любой из источников, модель заново спрашивает `GetMyAtlasUseCase`: гость получает пустой список, даже если в базе остались чужие кадры. Картинка строки берётся из снимка пользователя или из адреса в JSON.

**Листинг 3.** Два источника в одном MediatorLiveData

```java
private final MediatorLiveData<Library> library = new MediatorLiveData<>();
private final MutableLiveData<List<CloudType>> catalog = new MutableLiveData<>();

library.addSource(roomSightings, value -> {
    sightings = atlasUseCase.execute();
    emit();
});
library.addSource(catalog, value -> {
    types = value == null ? new ArrayList<>() : value;
    emit();
});
```

`emit()` собирает `Library`: список родов для сетки, строки атласа без даты и профиль со счётчиком «сколько кадров какого рода». Каталог, атлас и профиль подписаны на `library()`. Сохранение карточки пишет Room, поток базы срабатывает, и атлас с профилем обновляются без ручного `bind()` в `onResume`.

## 6. Вывод

Экраны CloudID обновляют интерфейс из LiveData и вызывают domain через ViewModel. ViewModel переживает поворот экрана, фабрика передаёт ей use-case без Context. `MediatorLiveData` в `HomeViewModel` соединяет замоканный каталог и наблюдения Room: сетка, атлас и состав профиля читают один снимок. Гость не видит и не сохраняет атлас.
